## 一、背景与目标

当前「AI 服务配置」模块（前端 `AiConfig.vue` → backend `AiConfigController` 代理 → ai-gateway `AdminController`）中，**模型名（model 字段）依赖人工凭记忆填写**。一旦写错（如本系统近期出现的 `google/gemma-4-e2b` 契约失败问题），需要逐个通道试错排查。

本方案实现「**从已知 API 地址主动拉取模型列表**」：管理员填入 endpoint + API Key 后一键探测，系统列出该端点全部可用模型（数量 + 名称），供选择填入，杜绝手误。

## 二、调研：主流大模型服务模型列表接口规范

### 2.1 各协议规范对照表

| 协议 / 服务 | 请求方法与路径 | 鉴权方式 | 响应结构 | 模型名提取路径 |
| --- | --- | --- | --- | --- |
| **OpenAI 兼容**（OpenAI / DeepSeek / 智谱 / Kimi / 通义 / NVIDIA / vLLM / LM Studio / Ollama 兼容层） | `GET {base}/models` | `Authorization: Bearer {key}` | `{"object":"list","data":[{"id":"gpt-4o","object":"model","created":...,"owned_by":"system","context_window":...}]}` | `data[].id` |
| **Ollama 原生** | `GET {base}/api/tags`（无需鉴权） | 无（可选 Bearer） | `{"models":[{"name":"qwen2.5:7b","model":"qwen2.5:7b","size":...,"digest":...,"modified_at":...,"details":{"family":"qwen2","parameter_size":"7.2B"}}]}` | `models[].name`（兼容 `models[].model`） |
| **Anthropic** | `GET https://api.anthropic.com/v1/models?limit=1000` | `x-api-key: {key}` + `anthropic-version: 2023-06-01` | `{"data":[{"id":"claude-...","type":"model","display_name":"..."}],"has_more":...}` | `data[].id` |
| **Google Gemini** | `GET https://generativelanguage.googleapis.com/v1beta/models` | `x-goog-api-key` 头或 `?key={key}` | `{"models":[{"name":"models/gemini-2.0-flash","displayName":"...","supportedGenerationMethods":["generateContent"]}]}` | `models[].name`（需剥 `models/` 前缀） |
| **gRPC** | —（模型元数据查询行业标准为 REST；gRPC 用于推理流，如 Triton 的 `RepositoryModelQuery` 属推理框架内部协议） | — | — | 不在 Web 服务探测范围 |

### 2.2 关键技术要点结论

1. **行业事实标准是 OpenAI 兼容协议**：DeepSeek、智谱、Kimi、通义、NVIDIA、本地 LM Studio/vLLM，甚至 Ollama 自身都提供 `GET /models` 兼容端点。本系统 `providerType` 仅含 `OPENAI_COMPAT / MOCK / OLLAMA` 三类，探测实现聚焦前两者的原生协议即可全覆盖。
2. **端点拼接易错点**：OpenAI 生态的 baseUrl 惯例**已含版本段**（如 `https://api.deepseek.com/v1`），探测路径为 `{endpoint}/models`；Ollama 的 baseUrl **不含版本段**（`http://localhost:11434`），探测路径为 `{base}/api/tags`。若用户把 Ollama 地址填成 `/v1` 结尾，自适应降级时需先剥离 `/v1` 再拼 `/api/tags`。
3. **鉴权差异**：OpenAI 兼容用 `Bearer` 头；Ollama 本地服务通常无鉴权（Key 可空）；探测失败分类需区分 401/403（Key 问题）与 404（路径问题）——两者的处置建议完全不同。
4. **响应数据陷阱**（实测发现）：
   - NVIDIA `/v1/models` 单页返回 **83+ 条**记录，存在同 id 重复行 → 必须**去重**；
   - 个别端点会返回**缺失 `id` 字段的脏数据行** → 必须过滤；
   - 反向代理误配时可能返回 **HTML 错误页（200 状态）** → 必须做结构校验（响应是否以 `{` 开头且含约定字段），而非只看状态码；
   - `context_window` / `details.parameter_size` 等元数据字段**可选存在**，不能强依赖。
5. **异常场景分类**（统一错误码设计的基础）：

| 错误类型 | 触发场景 | 是否重试 | 用户处置建议 |
| --- | --- | --- | --- |
| `PARAM_INVALID` | 地址非 http/https、为空 | 否 | 检查 API 地址格式 |
| `CONNECTION` | 服务未启动 / 端口错误 / 连接拒绝 | **否**（重试只会翻倍等待） | 确认服务已启动、端口正确 |
| `TIMEOUT` | 连接超时（不重试）/ 读取超时（重试 1 次） | 连接否/读是 | 目标服务负载高或网络慢 |
| `HTTP_401/403` | API Key 无效/无权限 | 否 | 检查 Key 与账户权限 |
| `HTTP_404` | 路径拼接错误（如 baseUrl 多/少 `/v1`） | 否 | 核对 API 地址版本段 |
| `PROTOCOL_MISMATCH` | 200 但响应非模型列表结构（HTML 页/其他 API） | 否（降级尝试下一协议） | 确认该地址为模型服务端点 |
| `HTTP_429/5xx` | 限流 / 上游故障 | 是（1 次） | 稍后重试 |

## 三、技术方案设计

### 3.1 架构与职责分层（与现有体系无缝对齐）

```
前端 AiConfig.vue ──JWT(ROLE_DEPT_LEADER)──▶ backend AiConfigController（代理）
                                                │ X-API-Key
                                                ▼
                                   ai-gateway ModelProbeService（新增，探测核心）
                                   ├─ 端点归一化 + 参数校验
                                   ├─ 自适应协议探测（OpenAI → Ollama 降级）
                                   ├─ 解析/去重/排序 + 结构化输出
                                   └─ 结果内存缓存（TTL 5 分钟，重复探测免外呼）
                                                │
                                                ▼
                                   sys_ai_provider_config.model（探测结果最终落库字段，零表结构变更）
```

**设计决策**：

- **探测核心放 ai-gateway**：与 `OpenAiCompatProvider` / `OllamaProvider` 同层，API Key 解密与不落日志的安全语义完全复用；backend 一律代理（延续 `AiConfigController` 现有模式），Key 永不出网关。
- **不新增数据库表**：探测结果为实时数据（模型列表会随服务端变化），前端选择后写入现有 `model` 字段；网关侧仅做 5 分钟 TTL 内存缓存优化重复探测。
- **与 35 次/分钟限流的关系**：`GET /models` 是元数据查询，不消耗模型推理配额（NVIDIA/OpenAI 均不计费不计次），且走独立 HTTP 客户端不经 Provider 链，不影响对话限流。

### 3.2 全流程设计

**① 接口探测**

- 双协议自适应：显式 `providerType` 时只走对应协议；未指定时先 OpenAI（`{endpoint}/models`），命中 `HTTP_404` / `PROTOCOL_MISMATCH` / `CONNECTION` 时降级 Ollama（剥 `/v1` 尾后拼 `/api/tags`）；`HTTP_401/403` **不降级**（服务存在，仅 Key 问题，降级结果更具误导性）。
- HTTP 客户端：连接超时 5s / 读取超时 10s（探测是轻请求，远短于对话 60s）；禁重定向到非 http。
- 两个新端点：
  - `POST /v1/admin/ai-configs/probe-models` — body `{providerType, endpoint, apiKey?}`，**未保存配置**即可探测（表单填写过程中使用）；
  - `GET /v1/admin/ai-configs/{id}/models` — **已保存通道**一键探测（服务端解密 Key，用户无需重新输入）。

**② 参数校验**

- endpoint 必须 `http://` / `https://` 前缀（防 file/ftp 等协议 SSRF 面）；尾部 `/` 归一化；`providerType` 枚举校验；`apiKey` 可空（Ollama 本地服务无鉴权）。

**③ 数据解析**

- OpenAI：校验响应以 `{` 开头且含 `data` 数组 → 逐行提取 `data[].id` / `data[].owned_by` / `context_window`；
- Ollama：校验含 `models` 数组 → 提取 `models[].name`（回退 `.model`）与 `details.family` / `parameter_size`；
- 防御式解析：单行解析失败跳过该行（不整体失败）。

**④ 错误重试**：按 2.2 第 5 点分类执行——仅 `读超时 / 429 / 5xx` 重试 1 次（间隔 300~500ms），其余快速失败；单次探测总耗时预算 ≤ 13s。

**⑤ 结果去重与排序**：`LinkedHashSet` 按模型 id 保序去重 → 按名称字典序排序输出；计数取去重后数量（真实可用数）。

**⑥ 结构化输出契约**（前后端一致）：

```json
{
  "success": true,
  "protocol": "OPENAI_COMPAT",
  "endpointUsed": "https://integrate.api.nvidia.com/v1/models",
  "count": 83,
  "durationMs": 790,
  "models": [{"id": "z-ai/glm-5.3-flash", "ownedBy": "z-ai", "protocol": "OPENAI_COMPAT"}],
  "cached": false,
  "errorType": null,
  "errorMessage": null
}
```

**⑦ 结构化存储**：探测结果实时返回不落库（防过期数据误导）；用户选定模型写入 `sys_ai_provider_config.model`（现有列，零迁移）；网关内存缓存以「协议+归一化 endpoint+Key 摘要」为键，TTL 5 分钟、容量上限 32 条（LRU 淘汰）。

### 3.3 安全要点

- API Key 仅经 `Authorization: Bearer` 头传输；探测日志只记 endpoint 与错误分类，**不记 Key、不记完整响应体**；
- 已保存通道探测（`/{id}/models`）由服务端解密 Key，前端全程无 Key 明文；未保存探测（`/probe-models`）Key 由表单一次性提交、不存储；
- 权限与现有一致：backend 端 `ROLE_DEPT_LEADER` + `@OperLog` 审计；gateway 端 `X-API-Key` 服务间认证（`ApiKeyFilter`）。

## 八、使用说明与注意事项

### 8.1 使用方式

1. **新增/编辑通道**（AI 服务配置 → 新增/编辑）：填好「通道类型」「API 地址」（与「API Key」）后点「探测模型」→ 模型名输入框变为下拉，提示「探测到 N 个模型（协议，耗时）」→ 下拉选择（保留手输能力）；探测失败显示错误分类与处置建议。
2. **已保存通道快速核对**：表格行点「探测模型」→ 弹窗展示该端点当前全部可用模型清单（含协议/耗时/缓存标记）。
3. **独立验证工具**（不依赖系统，可用于排查）：

```bash
# 全场景自测（内置 Mock，覆盖 10 类协议/异常场景）
java tools\model-probe\ProbeTool.java selftest
# 对任意已知 API 地址探测（可带 Key）
java tools\model-probe\ProbeTool.java probe https://integrate.api.nvidia.com/v1
```

### 8.2 注意事项

- 探测结果**实时返回 + 5 分钟缓存**：缓存期内重复探测标记 `cached=true`；如需强制最新，编辑 API 地址或等待 5 分钟；
- OpenAI 兼容端点地址惯例**已含 `/v1`**（如 `https://api.deepseek.com/v1`）；Ollama 填**根地址**（如 `http://localhost:11434`）——填错时自适应逻辑会尝试纠正并在响应中提示；
- 部分端点（如 NVIDIA）`/models` 不要求鉴权，探测成功不代表对话通道 Key 有效，**「测试连接」仍需单独执行**；
- Ollama 需安装并启动服务后探测才可用（本机当前未安装，探测返回 `CONNECTION` 属预期）。
