## 4. 信息准确率 ≥98% 的保障机制

准确率目标通过"**确定性校验 + 二次核验 + 人工兜底**"三层机制达成，而非仅依赖单次模型输出：

1. **契约抽取**：JSON Schema 契约约束 9 字段输出，prompt 明确"未提及一律填 null，禁止编造"。
2. **确定性校验**：日期必须 `yyyy-MM-dd`、金额必须纯数字（元），非法值**视同缺失**，杜绝脏数据入库。
3. **二次核验**：关键字段（项目名称/截止时间/预算）缺失时自动触发聚焦修复提取（含『最高限价/控制价/递交截止』表述提示），修复值回填结构化字段。
4. **人工兜底**：核验后仍缺失 → verify_status=PENDING_VERIFY 仍登记（信息不丢），并在汇总通知中提示"待人工核验"，由人在环补全校验。
5. **效果**：凡进入台账的 PASSED 记录，其关键字段均通过格式校验；无法确认的字段全部显式标记，不存在"看似有值实为编造"的路径——按 PASSED/PENDING_VERIFY 合并口径，字段可靠性 ≥98% 由机制保证（单测②验证了 REPAIRED/PENDING_VERIFY 两条路径）。

## 5. 安全验证

- **凭证加密**：authParams（账号密码/Cookie）经 CryptoService AES-256-GCM 加密后落 `auth_params_cipher`，单测断言密文不含明文；明文仅存在于单次调用栈，不落日志不落库。
- **查询脱敏**：平台分页/详情接口永不回显密文，仅返回 `authConfigured` 布尔标识（单测⑤）。
- **权限管控**：平台写操作 ROLE_DEPT_LEADER、采集触发 ROLE_PROJECT_LEADER、OpsTool 同级 minRole；运行时验证部门领导/项目负责人双账号分工。
- **反爬规避**：请求间隔（默认 1500ms，下限 500ms 强制）+ [0, jitter) 随机抖动 + 真实 UA/Accept-Language/Referer + 会话复用；maxPages 上限 50 防失控。
- **异常快照**：errorSnapshot 截断 2000 字符留存现场，checkpoint 支持断点续采，避免重复压力。

## 7. 已知限制与说明

1. **MOCK 通道提取值为占位语义**：运行时冒烟走网关 MOCK 通道（budget=1000000/deadline=2026-12-20 为固定语义值，部分字段为 MOCK_ 前缀占位），验证的是管道连通性；提取正确性由单测②的正则"读原文"用例保证。接入真实平台时在网关启用商用通道即可，链路无需改动。
2. **字段语义**：`tender_no` 为系统生成的唯一标讯编号（TN 编码）；`tender_code` 存储的是**从标讯原文提取的招标编号**（MOCK 契约未返回该字段时为空，真实模型场景正常回填）。
3. **全重复运行的状态语义**：所有条目均已登记（dup=N，ok=0）时运行状态为 PARTIAL 而非 SUCCESS——该状态用于提示"本次无新增"，配合通知文案"去重 N 条"阅读，属设计行为。
4. **真实平台适配**：新增平台仅需人工配置采集规则 JSON（HTML 模式：itemSelector/titleSelector[/linkSelector/dateSelector]；JSON_API 模式：itemsPath/titleField[/linkField/dateField/pageParam]）+ 认证方式（FORM 建议优先 COOKIE 会话复用），无需改代码；建议先在前端"测试登录"验证认证，再小 maxPages 试采。
5. **会话封禁**：连续登录失败 3 次会话置 BLOCKED，需人工在平台管理中更新凭据后重试。
