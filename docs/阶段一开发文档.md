## 1. 阶段一目标与范围

**目标**：打通「业务事件 → Agent 建议生成 → 人工审批 → 动作执行」最小闭环，并把自有业务能力经 MCP 暴露给 Dify 编排底座与 Hermes 主 Agent，实现外部 Agent 可直接调用本系统业务工具。

## 2. 架构与数据流

```
业务操作（建项目/建任务/状态流转/阶段完成）
    │  同事务内发布 DOMAIN 事件（bizKey 幂等）
    ▼
EventBusService（DB 事件表，3s 轮询，指数退避重试，DEAD 死信）
    │  按 eventType 分发到 DomainEventHandler SPI
    ▼
DecisionAdviceEventHandler × 4（新增消费者，零侵入既有业务）
    │
    ▼
DecisionAdviceService（阶段一确定性模板，不耗 LLM 配额）
    ├─ 场景规则 → 建议（confidence/riskLevel/requiresApproval/evidence）
    ├─ HITL：requiresApproval=1 → 审批参数 HMAC-SHA256 锁定
    ├─ 落库 agent_decision_advice
    └─ 站内信推送 target_user（GENERIC_REMIND 模板）
    ▼
决策建议中心（/ai/advice 前端页）
    └─ 部门领导采纳（HMAC 重算校验 → 动作执行）/ 驳回
         └─ AUTO_ASSIGN_TASK → TaskService.assign（阶段一唯一动作）

并行通道：
Dify / Hermes ──POST /api/mcp（X-API-Key）──▶ McpServerController
    └─ McpProtocolService（JSON-RPC 2.0：initialize/tools/list/tools/call/ping）
         └─ McpToolRegistry（8 个业务工具：任务/项目/投标/建议/晨报）
```

## 3. 关键设计决策

| 决策 | 方案 | 理由 |
| --- | --- | --- |
| MCP Server 实现方式 | 零依赖手写 JSON-RPC（Streamable HTTP 最小面） | 避免 Spring AI SDK 版本矩阵风险；协议面覆盖 Dify/Hermes 客户端调用链；阶段二可选升级官方 SDK |
| 建议生成 | 确定性规则模板 | 阶段一零 LLM 消耗，规避 35 次/分限流；LLM 生成与数据飞轮为阶段二 |
| MCP 端点鉴权 | SecurityConfig 白名单 + 控制器内 API Key 常数时间校验 | 外部 Agent 无 JWT 登录态；密钥经 `app.mcp.api-key` 配置 |
| 审批防篡改 | HMAC-SHA256 锁定 approvalParamsJson | 业界 HITL 审批流共识模式；执行前重算比对 |
| 事件幂等键 | project:{id} / task:{id} / task:{id}:{from}:{to} | 状态重复合法流转（0→1→0→1）需各自触发建议，不按实体幂等 |
| 循环依赖处理 | DecisionAdviceService 经 ObjectProvider<TaskService> 延迟获取 | TaskService→EventBus→Handler→AdviceService→TaskService 构造环 |
| 预算护栏 | 执行前检查 budget_used ≥ budget_limit 拦截 | 字段阶段一预留，精确 LLM 记账依赖网关调用日志关联（阶段二） |

## 4. 场景建议规则（阶段一 5 类）

| 场景 | 触发事件 | 内容 | 置信度 | 风险 | 审批 |
| --- | --- | --- | --- | --- | --- |
| 立项预审 | PROJECT_CREATED | 阶段模板核对/风险登记/成员确认 | 0.90 | LOW | 否 |
| 任务待指派 | TASK_CREATED（assigneeId 空） | 建议指派给创建人 → **AUTO_ASSIGN_TASK 动作** | 0.86 | MEDIUM | **是** |
| 任务要素确认 | TASK_CREATED（已有指派） | 工时/截止核对、大任务拆解 | 0.90 | LOW | 否 |
| 截止期预警 | TASK_STATUS_CHANGED（超期未完成） | 逾期天数 + 延期/升级建议 | 1.00 | HIGH | 否 |
| 验收预审 | TASK_STATUS_CHANGED →2 | 交付物一致性/验收标准/工时偏差清单 | 0.88 | LOW | 否 |
| 验收后续 | TASK_STATUS_CHANGED →3 | 跨域联动提示（归档/交付/回款） | 0.90 | LOW | 否 |
| 阶段完成后续 | PROJECT_PROGRESS_UPDATED（PHASE） | 下阶段启动/门禁评审提醒 | 0.90 | LOW | 否 |

## 7. 已知边界与阶段二衔接

1. MCP 端点不提供 SSE 流（GET 405）——Dify/Hermes 无流模式可用，符合规范
2. AUTO_ASSIGN_TASK 建议指派目标为「任务创建人」（确定性规则），LLM 智能指派为阶段二
3. advice.approval 动作执行为同步直调（阶段二迁 A2A Task 状态机）
4. 预算记账为占位语义（阶段一不递增），精确记账依赖网关调用日志关联
5. 建议无 LLM 参与 → 不受 35 次/分限流影响；MCP 工具中 tender.collect 经队列异步执行
