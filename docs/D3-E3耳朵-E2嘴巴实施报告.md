## 二、设计要点

1. **能力探测降级**：`getSpeechRecognitionCtor()` 探测 `SpeechRecognition/webkitSpeechRecognition`；`ttsAvailable` 探测 `speechSynthesis`。不支持的浏览器对应按钮直接隐藏（不是禁用），无能力报错噪音。
2. **连续识别健壮性**：浏览器语音服务会周期性断流（onend），`wantListening` 标志位自动重启，用户点击停止才真正结束；`not-allowed/service-not-allowed` 权限错误置 false 不再重启。
3. **TTS 声音择优**：zh-CN 本地声音包 > 任意 zh 声音 > 默认；`onvoiceschanged` 异步加载后重新择优。
4. **朗读内容净化**：代码块替换为「（代码块略）」、剥离图片/链接/标题/强调标记、表格行去竖线——避免读出乱码语法。
5. **自动播报范围**：仅 `msgType === 'text'` 的 AI 回复自动朗读（Hermes 卡片/任务卡/流程卡不朗读）。

**浏览器端实测说明**：Web Speech API 依赖浏览器运行时（Chrome 内核 + 麦克风权限 + Windows 语音服务），Node 环境无法自动化实测语音输入/播报音频，需用户在浏览器手动验收（点击麦克风说话 → 断句追加输入框；点朗读按钮 → 播报回复）。逻辑层已通过类型检查与静态审查闭环。

## 四、已知问题

1. **STT 依赖浏览器服务**：Edge/Chrome 的语音识别走微软云服务（无需 Key），离线环境不可用——按钮隐藏即为降级态。
2. TTS 声音包质量取决于 Windows 安装的语言包（缺中文包时用默认声音，语调一般但可用）。
3. `rec-pulse` 动画用 `::after` 边框扩散，Element 按钮内布局已适配（relative 定位）。
