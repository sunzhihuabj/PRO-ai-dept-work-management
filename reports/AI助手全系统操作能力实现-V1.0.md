## 1. 功能概述

在统一 AI 助手（AI 工作台）中落地「自然语言对话驱动全系统操作」能力：用户以日常口语即可完成跨版块的**信息查询、数据录入、状态推进、配置确认**等操作，无需进入多级菜单。助手对系统版块的功能边界、字段定义、状态枚举、业务规则、权限范围建立结构化认知，所有反馈严格贴合系统数据规范。

**能力总览**：13 个业务版块、33 个注册工具（19 只读 + 14 写入）、4 类安全机制、8 类场景验证全部通过。

## 2. 架构与实现

### 2.1 代码结构（backend/src/main/java/com/dept/mgmt/aiworkspace/ops/）

| 文件 | 职责 |
|---|---|
| `OpsTool.java` | 工具定义模型：名称/版块/说明/只读标记/参数声明/所需角色/精细权限点/执行器/展示列 |
| `OpsParam.java` | 参数声明：名称/类型（string·number·date·bool）/必填/中文说明/枚举值 |
| `OpsToolRegistry.java` | 工具注册表（33 工具）+ 版块知识卡（SYSTEM_KNOWLEDGE）+ 项目/成员名称解析 + 状态枚举翻译 + Markdown 渲染 |
| `OpsPendingStore.java` | 写入操作确认暂存（会话级，TTL 5 分钟） |
| `SystemOpsService.java` | 主流程：意图判定 → 参数校验 → 权限校验 → 执行/确认 → 合规反馈 |

### 2.2 对话路由（AiChatService.routeAndReply）

```
用户消息
 ├─ ① 流程创建意图（规则：创建XX流程）→ 流程草稿卡片（T-408 既有）
 ├─ ② 系统操作意图（SystemOpsService，T-411 新增）
 │     ├─ 待确认操作存在且用户回复「确认/取消」→ 执行/取消
 │     ├─ LLM 判定（网关 JSON 契约 + 知识卡 + 33 工具目录 + 8 个 few-shot 示例）
 │     │    action=tool  → 校验/权限/执行（只读即时，写入待确认）
 │    │    action=agent → 转交 Agent 体系（日报/资格比对等 AI 分析类，26 能力点）
 │    │    action=chat  → 基于知识卡直接回答（普通咨询/闲聊）
 │     └─ 写入意图硬兜底：消息含写入动词但被误判 chat/agent → 强制重判定 → 仍失败则给标准引导（杜绝"假执行"）
 ├─ ③ Agent 意图（MasterAgentService 26 能力点，T-107 既有）
 └─ ④ 通用对话（网关多轮上下文，既有）
```

模型调用统一经 AiGatewayClient → ai-gateway（35 次/分钟用户限流、降级链 NVIDIA→EEOK→LM→MOCK），单条消息 1~2 次调用，远低于限额。

### 2.3 版块知识卡（注入 LLM 的系统认知）

`OpsToolRegistry.SYSTEM_KNOWLEDGE` 按版块声明：任务/项目状态与优先级枚举、合同状态机与 G1 门（四项收款比例合计 100%）、样机开工卡点（齐套≥95%+交底签字）、交付验收触发线（30%/85%、三方签字）、ECN 实施联动（旧方案归档+任务回收）、档案借阅规则（电子不可实物借出）、售后闭环必填（根因+方案）、单号自动生成、红线（删除/资金审批不开放对话执行）等。模型回答业务问题必须以知识卡为准。

## 4. 对话交互流程规范

### 4.1 查询类（一步完成）

```
用户：查一下生效状态的合同
助手：| # | 编号 | 合同名称 | 客户 | 金额(元) | 状态 | 风险等级 |
     | 1 | HT-202611-0004 | T406浏览器验证合同 | 浏览器客户 | 500000.00 | EFFECTIVE | — |
     （共 1 条，最多显示 10 条，可用更精确的条件筛选）
```

### 4.2 写入类（两段确认，5 分钟有效）

```
用户：帮我创建一个任务：项目「三一重能」任务名称「月度盘点」优先级高
助手：将执行「创建任务」（任务管理），参数如下：
     - 所属项目名称：三一重能
     - 任务名称：月度盘点
     - 优先级：高
     回复「确认」执行，「取消」放弃（5 分钟内有效）。
用户：确认
助手：任务创建成功：月度盘点（ID=2，项目：三一重能）
```

### 4.3 缺参追问（仅业务必需字段，一次问全）

```
用户：帮我创建一个任务
助手：执行「创建任务」还需要补充：所属项目名称；任务名称
```

### 4.4 越权拒绝 / 业务校验失败

```
普通账号：帮我创建一个项目：…
助手：「创建项目」需要 部门领导 权限，当前账号无权执行该操作。

用户：帮我创建任务：项目「不存在XYZ」…
助手：「创建任务」未能执行：未找到项目「不存在XYZ」，请确认项目名称（可先说「查一下项目」核对）
```

### 4.5 咨询/闲聊（基于知识卡，不索要无关信息）

```
用户：合同的审批流程是什么？
助手：合同按 草稿→会签→审批→用印→生效 流转，会签门要求四项收款比例合计100%，审批/用印仅部门领导可操作。
```

## 5. 数据校验规则清单

### 5.1 声明式校验（LLM 输出 → 执行前强制）

| 规则 | 处理 |
|---|---|
| 必填缺失 | 不执行，按参数声明生成标准追问（只含必填项，禁止索要无关信息） |
| 枚举越界 | 参数「X」仅支持：a/b/c（中文枚举 ↔ 系统编码双向映射） |
| 类型错误 | 数字/金额/日期（yyyy-MM-dd）转换失败给可读提示 |
| 工具不存在 | 「该操作暂不支持对话执行」+ 能力指引 |

### 5.2 业务解析校验（OpsToolRegistry 内）

| 规则 | 处理 |
|---|---|
| 项目名解析 | ID 精确 → like 模糊 → 口语化去尾「项目」→ 双向包含兜底；零候选给核对建议，多候选列编号+名称让用户指明 |
| 成员解析 | 账号精确/姓名 like → 双向包含兜底；同上 |
| 合同解析 | contractNo like（HT 编号） |
| 工时区间 | 0.5–24 小时（WorkHourDTO 注解兜底） |
| 口语化日期 | LLM 按当天日期换算为 yyyy-MM-dd |

### 5.3 权限校验（执行前双重）

| 工具声明 | 判定 |
|---|---|
| minRole（如 ROLE_DEPT_LEADER） | 部门领导兜底放行，否则拒绝并给出所需角色中文名 |
| permCode（如 api:contract:link） | FinePermissionService.hasPerm(userId, code)，领导兜底 |

### 5.4 防幻觉三重保险

1. 判定规则明确「禁止 chat 声称已执行（实际执行由系统完成）」+ 8 个 few-shot 示例；
2. 消息含写入动词（创建/登记/审批/借阅…）但 LLM 误判 chat/agent → 强制带「上一轮误判」提示重判定；
3. 重判定仍非 tool → 拒绝输出，给标准句式引导；**所有写入必须经用户「确认」并由 Service 真实落库**。

## 7. 已知边界与后续建议

1. **写入默认值**：未指定优先级/负责人时按系统默认（中优先级/空负责人），回执中如实显示；
2. **2B 本地模型**：意图判定准确率依赖 few-shot 与硬兜底（当前 LM 通道 gemma-4-e2b）；切换更强商用通道后准确率自动提升，无需改代码；
3. **建议扩展**：① 消息确认回执增加前端操作卡片（含一键确认/取消按钮）；② 工具目录支持按用户角色裁剪（普通账号隐藏领导专属工具，减少无效选择）；③ 增加执行结果跳转链接（如「任务 ID=2 → 点击查看详情」）。
