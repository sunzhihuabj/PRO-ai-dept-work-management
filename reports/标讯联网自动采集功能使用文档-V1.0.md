## 1. 功能启用的前置条件与准备工作

### 1.1 环境前置条件

| 项 | 要求 | 验证方法 |
| --- | --- | --- |
| 后端服务 | dept-mgmt 后端运行中（默认 8081） | 登录系统正常 |
| AI 网关 | ai-gateway 运行中（默认 8090），至少一个通道启用 | 管理员在 AI 配置中确认通道状态；MOCK 兜底通道默认内置 |
| 数据库 | 已执行 `database/08_tender_collect.sql`（3 张新表 + tender_notice 扩展列 + AGT-27 能力点） | `SHOW TABLES LIKE 'tender_%'` |
| 网络连通 | 后端服务器可访问目标招标平台（列表页/详情页/登录页） | 服务器上 `curl` 或浏览器访问列表页 URL |
| 目标平台调研 | 明确：列表页 URL、分页方式、列表结构（HTML 还是 JSON 接口）、认证方式 | 见 1.2 |

### 1.2 平台结构调研（配置前必做）

在浏览器中打开目标平台，确认四件事：

1. **列表页 URL 与分页方式**：翻到第 2 页观察 URL。形如 `list/2.html` 用 `{page}` 占位；形如 `list?page=2` 记下参数名（如 `page`）配 `pageParam`；URL 不变的单页站点则两者都不填。
2. **数据形态**：右键"查看网页源代码"能看到标讯标题 → HTML 模式；标题需 F12 Network 中从 XHR 接口取 → JSON_API 模式（此时列表页 URL 应填该接口地址）。
3. **详情页链接**：标题链接是绝对地址还是相对路径（相对路径需配置详情页 URL 前缀）。
4. **认证方式**：免登录可看 → NONE；需登录且无验证码/简单验证码 → FORM；登录流程复杂（滑块/短信/风控）→ COOKIE 会话复用（**推荐优先**，最稳定）。

### 1.3 账号准备

- **平台配置（新增/编辑/删除/启停/测登录）**：部门领导账号（ROLE_DEPT_LEADER），如 `sunzhihua`。
- **触发采集**：项目负责人账号（ROLE_PROJECT_LEADER），如 `lihailong`。
- **目标平台凭据**：FORM 模式准备账号密码；COOKIE 模式按 4.2 节方法提取浏览器 Cookie。

## 2. 操作指引（逐步）

### 第一步：新增采集平台（部门领导）

**入口**：菜单「投标管理 → 采集平台管理」→ 右上角**新增平台**按钮 → 填写表单 → 保存。

| 表单项 | 填写说明 |
| --- | --- |
| 平台名称* | 唯一，如「国家电网电子商务平台」 |
| 认证方式* | 免登录 / 账号密码 / Cookie 复用 三选一 |
| 登录入口 URL | 仅账号密码模式必填 |
| 登录凭据 | 账号密码模式填账号+密码；Cookie 模式粘贴 Cookie 串。**加密落库，任何接口不回显** |
| 列表页 URL* | 支持 `{page}` 占位符；无占位符时配合采集规则中的 pageParam |
| 详情页 URL 前缀 | 列表项为相对链接时必填（如 `https://x.com/notice/`） |
| 采集规则* | JSON 配置，详见第 4 节（表单已预置 HTML 模式模板，直接改选择器即可） |
| 请求间隔/抖动/最大页数 | 反爬参数，保持默认即可（详见 4.3） |

### 第二步：测试登录（部门领导）

平台列表点击**测登录**：
- FORM 模式：真实执行一次表单登录并校验会话；
- COOKIE 模式：校验粘贴的 Cookie 是否有效；
- NONE 模式：探活列表页可达性。

返回 `success: true` 再进入下一步；失败按第 7 节排查。

### 第三步：触发采集（三个入口任选）

**入口 A —— 界面按钮**：平台列表目标行点击**采集**（项目负责人可见可操作；同步执行，运行期间按钮转圈，页数多时需耐心等待）。

**入口 B —— AI 对话（推荐，Agent 自动执行）**：在 AI 助手对话中：

```
用户：查一下可用的采集平台
→ Agent 调用 tender.collectPlatforms，返回启用中平台清单（含 ID）

用户：采集平台 1 的最新标讯
→ Agent 调用 tender.collect（platformId=1），同步执行后返回：
   运行 #5，状态 SUCCESS：发现 6 条，登记 6 条，去重 0 条，待人工核验 0 条
```

采集属于 Auto 级能力（无需人工确认即自动执行，因登记带完整溯源可复核）。断点续采对 Agent 说"**从断点续采平台 1**"（`resume=true`）。

**入口 C —— REST API**：

```http
POST /api/v1/tender-collect/run
Authorization: Bearer <token>
Content-Type: application/json

{"platformId": 1, "resume": false}
```

### 第四步：查看运行监控

页面下半部「**采集运行监控**」表格实时展示每次运行：运行#、平台、触发方式（AGENT/AGENT_DIALOG/MANUAL）、状态、登录结果、页数、发现/登记/去重/待核验数量、时间。点击**详情**打开抽屉，查看完整指标、断点检查点（doneUrls 列表）与异常现场快照。可按状态（成功/部分成功/失败/运行中）筛选。

### 第五步：核对登记结果与人工核验

- 登记成功的标讯进入「投标管理 → 标讯管理」台账：系统自动生成 **TN 编号**、来源平台、采集时间（`import_source=AGENT_COLLECT`、`source_url` 原文链接可溯源）；标题/预算/截止时间/采购方等由 AI 提取回填，全文存于 raw_text。
- `verify_status=PENDING_VERIFY`（待人工核验）的记录：关键字段（项目名称/截止时间/预算）未能确认，但已登记不丢失，**支持二次编辑**补全后在标讯管理中正常使用。
- 采集完成后触发人收到站内信「【标讯采集完成】」，含状态与四项计数；登录失败、运行异常另有告警通知。

## 3. 各配置项详细说明与推荐设置

### 3.1 基本项

| 配置项 | 可选值/约束 | 默认 | 推荐设置 |
| --- | --- | --- | --- |
| 认证方式 authType | NONE / FORM / COOKIE | NONE | 免登录平台 NONE；其余**优先 COOKIE**，仅简单表单用 FORM |
| 请求间隔 requestIntervalMs | ≥500ms（低于强制按 1500） | 1500 | 1500~3000ms；平台有明确频率条款时从严 |
| 抖动上限 jitterMs | ≥0 | 800 | 800~1500ms（间隔+随机抖动=拟人节奏） |
| 单次最大页数 maxPages | 1~50 | 3 | 首次试采 1~3 页，稳定后按需调大 |
| 详情页 URL 前缀 | http(s) 前缀 | 空 | 列表项相对链接时必填 |

### 3.2 凭据 authParams（明文仅入参，服务端即时 AES-256-GCM 加密）

| 模式 | 键 | 说明 |
| --- | --- | --- |
| FORM | `username` / `password` | 平台登录账号密码 |
| COOKIE | `cookie` | 浏览器登录后的 Cookie 串 |

**Cookie 获取方法**：浏览器登录目标平台 → F12 打开开发者工具 → Network 刷新页面 → 任选一个对列表页的请求 → Request Headers 复制完整 `Cookie` 值（或 Console 执行 `document.cookie`，但前者更完整，HttpOnly 字段只能从 Network 取）。**注意**：应在与部署后端同一出口网络环境下登录复制，部分平台将 Cookie 与 IP 绑定。

### 3.3 采集规则 collectRules（JSON）

```jsonc
{
  "mode": "HTML",                    // HTML=网页解析；JSON_API=接口解析
  "userAgent": "",                   // 可选，自定义 UA；空=默认桌面 Chrome UA
  "list": {
    // —— HTML 模式 ——
    "itemSelector": ".news-list li", // 每条标讯的列表项元素
    "titleSelector": "a.title",      // 列表项内标题元素（取 text 作标题）
    "linkSelector": "a.title",       // 可选，详情链接元素（title 自带 href 时可省）
    "dateSelector": ".date",         // 可选，发布日期元素
    // —— JSON_API 模式 ——
    "itemsPath": "data.rows",        // 数组路径，按 . 逐层取
    "titleField": "title",           // 标题字段名
    "linkField": "url",              // 详情链接字段名
    "dateField": "publishDate",      // 发布日期字段名
    "pageParam": "page"              // 分页参数名（URL 含 {page} 时不用配）
  },
  "detail": {
    "contentSelector": ".content",   // HTML 详情正文选择器；不配=整页可读文本
    "contentField": "data.content"   // JSON_API 详情正文字段路径（与上二选一）
  },
  "login": {
    "usernameField": "username",     // 表单账号字段名（默认 username）
    "passwordField": "password",     // 表单密码字段名（默认 password）
    "hiddenFields": {"lt": "..."},   // 可选，隐藏域（如 CAS 的 lt/execution）
    "successKeyword": "退出登录",     // 登录成功后页面出现的标识词（也用于会话校验）
    "failKeyword": "密码错误",        // 可选，登录失败页标识词
    "captchaField": "verifyCode",    // 可选，验证码输入框字段名（配了才启用识别）
    "captchaImgSrc": "/captcha.jpg"  // 验证码图片地址（相对/绝对均可）
  }
}
```

**三种平台结构示例**：

1. HTML 分页站点：`listUrl = https://x.com/list/{page}.html`，HTML 模式四选择器。
2. JSON 接口站点：`listUrl = https://x.com/api/notices` + `pageParam:"page"`，JSON_API 模式；详情也是接口时 `detailUrlPrefix` 配接口前缀、`detail.contentField` 配正文字段。
3. FORM 登录 + 验证码：authType=FORM + `login` 块完整配置；验证码识别走网关多模态通道，**单次尝试不重试**（避免轰炸验证码接口），通道不支持时明确报错并引导改用 COOKIE 模式。

### 3.4 触发参数

| 参数 | 说明 |
| --- | --- |
| `platformId` | 必填，目标平台 ID |
| `resume` | `true`=从上次断点续采（跳过已采集的 URL 与整页，追平增量）；默认 `false` 全新采集（已登记条目自动去重不重复入库） |

## 4. 注意事项、权限要求与约束条件

### 4.1 权限矩阵

| 操作 | 界面可见性 | 后端强制权限 |
| --- | --- | --- |
| 平台分页/详情/启用清单查询 | 所有登录用户 | 登录即可 |
| 新增/编辑/删除/启停/测登录 | 仅部门领导（isAdmin） | `ROLE_DEPT_LEADER` |
| 触发采集（界面/Agent/API） | — | `ROLE_PROJECT_LEADER` |
| 运行监控查询 | 登录用户 | 登录即可 |

### 4.2 约束与限制

1. **平台互斥**：同一平台同时仅允许一个采集运行（第二请求排队等待）。
2. **平台须启用**：停用状态触发会报"平台已停用，无法采集"。
3. **同步执行**：采集请求同步返回，耗时 ≈ 页数 × 每页条数 × (间隔+抖动) + 提取耗时。maxPages 大时请用 Agent 对话或 API 方式并在完成后看通知，避免界面长时间等待。
4. **频率强制**：间隔下限 500ms（防误配过快），maxPages 上限 50（防失控），每请求 3 次指数退避重试（1s/2s/4s）。
5. **会话封禁保护**：会话连续校验失败 3 次 → 状态 BLOCKED，**停止对该平台的自动访问**，需人工重新配置凭据并测登录。
6. **合规要求**：采集仅应面向本单位有合法访问授权的平台，遵守目标平台服务条款与频率要求；凭据仅用于授权账号自动登录。
7. **凭据安全**：AES-256-GCM 加密落库（密钥独立派生），接口永不回显明文；编辑时凭据留空 = 保留原值（避免误清空）。
8. **提取依赖模型通道**：模型通道不可用时提取失败、该条不登记（不影响其他条目），运行以 PARTIAL 收尾并告警——数据完整性优先，绝不写入未经提取确认的半成品。
9. **全重复运行**：所有条目均已登记时状态为 PARTIAL（去重计数=N、登记=0），表示"本次无新增"，非故障。

## 5. 预期效果与验证方法

### 5.1 正常执行后的预期

| 环节 | 预期结果 |
| --- | --- |
| 运行状态 | SUCCESS（全部提取登记）/ PARTIAL（部分待核验或全部去重）/ FAILED（登录失败等致命异常） |
| 标讯台账 | 新增 TN 编号记录：标题=AI 提取项目名称、预算/截止时间/采购方等结构化回填、`import_source=AGENT_COLLECT`、`source_url` 可点击溯源原文、`raw_text` 保留全文 |
| 提取校验 | `PASSED`（关键字段齐全且格式校验通过）/ `REPAIRED`（二次核验补全）/ `PENDING_VERIFY`（待人工核验，仍登记） |
| 通知 | 触发人收到「【标讯采集完成】…发现 N 条，登记 N 条，去重 N 条，待人工核验 N 条」；异常场景另收告警 |
| 幂等性 | 重复触发不产生重复台账（source_url 唯一键），运行报告去重计数 |

### 5.2 验证清单

1. 运行监控表：状态 SUCCESS、登记数>0、无异常快照；
2. 标讯管理列表：按创建时间倒序查看新记录，核对 TN 编号与字段；
3. 点开 `source_url` 与原文比对标题/预算/截止时间；
4. 站内信收到完成通知；
5. 再次触发同平台采集：登记=0、去重=上次登记数（幂等验证）；
6. Agent 对话查询：「最近一次采集结果」→ tender.collect 运行记录/运行监控数据一致。

## 6. 常见问题排查与处理

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 测登录返回失败（FORM） | 账号密码错误；successKeyword 配错（页面实际不含该词） | 核对凭据；用浏览器登录后看列表页出现什么固定词（如「退出登录」）填入 successKeyword |
| 提示「验证码 AI 识别不可用」 | 当前模型通道不支持多模态图片 | 改用 COOKIE 会话复用模式（推荐）；或切换支持多模态的通道 |
| COOKIE 校验失败 / 登录后很快失效 | Cookie 不完整（漏 HttpOnly 字段）；平台绑定 IP/UA；Cookie 自然过期 | 按 4.2 重新从 Network 复制完整 Cookie 串；在与后端同网络环境登录；过期后重新粘贴 |
| 会话状态 BLOCKED | 连续校验失败 ≥3 次（疑似封禁） | 编辑平台更新凭据 → 测登录成功后自动恢复 ACTIVE |
| 采集发现 0 条 | itemsPath / itemSelector 配错；列表是 JS 动态渲染 | HTML 模式用浏览器 F12 验证选择器能选中列表项；JSON_API 模式先直接访问接口确认返回结构与 itemsPath 层级 |
| 标题有了但详情全空/全是列表页内容 | linkField/linkSelector 未配置对；相对链接缺 detailUrlPrefix | 补配链接字段或 URL 前缀；JSON 相对链接以列表页 URL 为 base 解析 |
| 运行 PARTIAL、extractFailed=N、lastErrorType=EXTRACT | 模型通道不可用/超时（真实通道外呼失败） | 打开运行详情看 errorSnapshot 现场；管理员检查网关通道配置与配额；恢复后重新触发（未登记条目会重采） |
| 运行 FAILED、lastErrorType=LOGIN_FAILED | 登录失败（凭据/风控/验证码） | 收到告警通知；按 FORM/COOKIE 各自方式排查后重试 |
| 运行 FAILED、lastErrorType=NETWORK | 平台不可达（重试 3 次均异常） | 服务器上验证网络连通性与平台可用性；确认未触发对方风控 |
| 触发报「平台已停用，无法采集」 | 平台被停用 | 启用开关切换为启用 |
| 触发报权限不足（403） | 角色不符 | 采集需项目负责人 ROLE_PROJECT_LEADER；平台配置需部门领导 |
| 采集很慢 | 正常（限频拟人设计）；或平台响应慢触发退避重试 | 属预期行为；如需提速可在合规前提下下调间隔（≥500ms），或减少 maxPages 分批采集 |
| 界面"新增平台"按钮不显示 | 当前账号非部门领导 | 换部门领导账号操作 |
| 重复采集会不会登记重复数据 | — | 不会。source_url 唯一键去重，重复条目计入"去重"计数 |
| 断点续采怎么用 | 中断后想接着采 | Agent 说"从断点续采平台 X"或 API `resume:true`；系统按 checkpoint（lastPage+doneUrls）跳过已采条目 |
