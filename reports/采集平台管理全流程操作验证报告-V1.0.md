## 一、验证方式说明（重要）

本次验证原计划通过浏览器自动化执行真实的点击操作。经彻底排查，**本机 Trae 浏览器插件环境不完整，浏览器自动化无法启用**，根因链如下：

1. 浏览器工具通过 JSON-RPC 连接 `127.0.0.1:19234` 的 browser-bridge.exe（ticket 鉴权，超时 5s）；
2. bridge.exe 本应由 Chrome 扩展（ID `nbmnklcgnddbjafigmlhfjhefcfcgggn`，"TRAE SOLO Browser Bridge"）经 Native Messaging 拉起并对端协作；
3. 实测该扩展在 Chrome / Edge 所有用户 profile 的 Extensions 目录中均**未安装**，浏览器截图缓存目录为空——即浏览器功能在本机从未成功初始化；
4. 手动拉起 bridge 常驻监听 19234 后，工具能建立连接但所有请求超时（bridge 缺少扩展对端，无法驱动页面）；
5. 引导用户交互的 `browser_waiting_for_user_interaction` 工具在当前环境配置下不可用。

**启用指引**：在 Trae 客户端界面中完成浏览器插件的安装/引导流程（首次使用浏览器相关功能时 Trae 会提示安装 "TRAE SOLO Browser Bridge" Chrome 扩展），安装后即可用浏览器代理重跑本报告的 UI 级验证。

因此本次采用**替代验证方案**：前端结构核验（路由/菜单/按钮可见性/表单校验逻辑逐行核对源码）+ HTTP 契约级验证（完整走通 7 步流程对应的全部 API，请求经 `http://localhost:5173/api` 代理，与前端 axios 实际链路完全一致）。该方法可完全覆盖「数据提交与返回结果」「字段校验规则」「权限控制」等验证点；唯一无法直接覆盖的是浏览器内的视觉渲染与鼠标点击事件本身。
