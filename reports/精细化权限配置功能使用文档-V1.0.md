## 一、功能概述

在用户管理模块中新增**精细化权限配置**能力，支持三个维度为用户独立配置权限集合：

| 维度 | 配置入口 | 说明 |
|---|---|---|
| 部门维度 | 按部门 Tab / 按用户 Tab（所属部门快捷配置） | 权限分配到部门，部门内所有用户共享 |
| 固定职位维度 | 按职位 Tab（职位配置）/ 按用户 Tab（职位分配） | 职位长期持有，权限长期生效 |
| 临时职位维度 | 按用户 Tab（临时职位+有效期） | 阶段性岗位，到期自动失效 |

**合并规则**：三维度权限合并叠加（并集）；同一权限点效果冲突时，**临时职位 > 固定职位 > 部门维度**（高优先级维度的授予/拒绝覆盖低优先级维度）。

**灰度原则（重要）**：用户三维度均未配置任何权限时，**不启用精细控制**，行为与现有纯角色体系完全一致——存量用户零影响。一旦任一维度有配置记录，该用户即进入精细控制。

**管理员兜底（防自锁）**：ROLE_DEPT_LEADER（部门领导，系统最高角色）始终放行所有 @RequirePerm 校验，避免首个被配置精细权限的管理员把自己锁在配置界面之外。

## 二、权限点模型

权限点分三级（存于 `sys_perm_point` 表，种子共 243 个）：

| 类型 | 编码规范 | 示例 | 控制范围 |
|---|---|---|---|
| MENU 菜单级 | 前端路由 path | `/system/user` | 侧边栏菜单可见性（AppLayout 过滤） |
| BUTTON 按钮级 | `btn:<模块路径>:<动作>` | `btn:system/user:create` | 页面按钮显隐（v-perm 指令） |
| API 接口级 | `api:<模块路径>:<动作>` | `api:system/user:list` | 后端接口访问（@RequirePerm 校验） |

MENU 为树根，BUTTON/API 挂在对应 MENU 下。本期 BUTTON/API 种子覆盖全部 27 个业务菜单的标准动作（list/create/update/delete）+ 用户管理与权限配置特例动作；**接口级校验本期示范落地于系统管理域**（UserController、FinePermController 共 14 个接口），业务域接口扩展方式见第六节。

## 三、界面操作指南（系统管理 → 权限配置）

### 3.1 按用户 Tab
1. 下拉选择用户 → 展示其**职位分配表**（职位/性质/有效期/生效状态）。
2. **分配职位**：选择职位 + 性质（固定/临时）；临时职位必须配置起止时间（结束需晚于开始）。
3. **移除职位**：移除后相关权限立即回收。
4. **所属部门维度快捷配置**：显示用户所属部门的权限树，可直接勾选配置（写入部门维度，对全部门生效）。
5. **权限预览**：打开抽屉查看该用户分维度明细、冲突裁决、最终生效集合。

### 3.2 按部门 Tab
1. 组织架构树下拉选择部门 → 权限树操作（对该部门维度写入）。
2. 权限树操作：勾选节点 → **批量授予**（绿）/ **批量拒绝**（红，DENY 标记）/ **批量移除**（清除配置）；支持**应用模板**一键复用。

### 3.3 按职位 Tab
1. 职位下拉（含在持人数）→ 权限树操作（对该职位维度写入）。
2. **新建/编辑/删除职位**：职位被用户持有时不可删除；停用职位其权限立即失效。

### 3.4 变更日志 Tab
- 审计查询：按主体类型/维度/操作人/时间范围筛选，分页展示。
- 每条记录含：操作人、操作时间、主体（用户/部门/职位）、变更维度、操作类型、涉及权限点、**变更前后内容快照**（详情弹窗查看 JSON）。

### 3.5 权限树通用规则
- 节点标签：「已授予」= GRANT、「已拒绝」= DENY（显式拒绝标记）。
- 批量授予/拒绝 = upsert（同主体同权限点唯一）；批量移除 = 删除配置记录。
- 半选节点不参与批量操作（请展开勾选到具体子项）。

## 四、实时生效机制

1. **后端**：每次权限配置变更递增全局版本号并清空进程内权限缓存 → 用户下一次请求即按新配置重载权限（无需重新登录）。
2. **前端**：路由切换时轻量比对全局版本号（30 秒节流），版本变化即静默刷新权限 → 菜单/按钮可见性同步更新。
3. 多实例部署需升级为 DB 版本表方案（当前单机部署进程内缓存即可，见接口说明文档"扩展"）。

## 五、种子数据

- 示例职位：PRJ_SPECIALIST 项目专员 / GA_SPECIALIST 技改专员 / TMP_REVIEWER 临时评审专家。
- 权限模板：TPL_SYS_READONLY 系统管理·只读 / TPL_SYS_FULL 系统管理·完全。
- 不预置任何权限分配（灰度原则）。执行脚本：`database/03_fine_permission.sql`（表已建好则可只执行种子段）。

## 六、开发扩展指南

### 6.1 新增接口级权限校验
```java
// Controller 方法上加注解即可（权限点需存在于 sys_perm_point）
@RequirePerm("api:task/list:create")
@PostMapping
public R<Long> create(...) { ... }
```

### 6.2 前端按钮级控制
```vue
<el-button v-perm="'btn:task/list:create'">新建任务</el-button>
<!-- 多权限点任一满足即显示 -->
<el-button v-perm="['btn:task/list:update','btn:task/list:delete']">操作</el-button>
```

### 6.3 新增权限点
向 `sys_perm_point` 插入记录（或在权限树挂接管理功能），MENU/BUTTON/API 三级，BUTTON 的 API 对应点编码将 `btn:` 前缀换为 `api:`。

## 七、已知边界与说明（如实披露）

1. **角色体系保持不变**：ROLE_XXX 角色校验（hasAuthority）继续生效，精细权限是增量叠加层；JWT 中的角色快照仍需重新登录才更新（角色变更非本次范围）。
2. **同维度冲突规则**：同一维度内多个来源（如两个固定职位）对同一权限点效果不一致时，DENY 优先（安全默认），冲突在预览中明示。
3. **临时职位过期**：不参与合并计算（自动失效），重新配置有效期后恢复。
4. **接口级覆盖范围**：本期 @RequirePerm 落地系统管理域 14 个接口（用户管理 7 + 权限配置 7 类管理动作）；业务域接口按 6.1 方式增量添加。
5. **多实例部署**：版本号/缓存为进程内实现，多实例需改造（接口说明文档"扩展"一节）。
