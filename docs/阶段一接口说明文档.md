### 1.2 采纳建议（HITL 审批）

```
POST /api/v1/agent-advices/{id}/approve
Authorization: Bearer <JWT>（仅 ROLE_DEPT_LEADER，否则 403）
Body: {"comment": "同意，指派给创建人"}
```

**行为**：
1. 状态必须是 PENDING（否则 409）
2. 含 approvalAction 的建议：重算 HMAC 比对 `approvalParamsJson`（不匹配 → 409「完整性校验失败」，防审批间隙篡改）
3. 校验通过 → 状态 APPROVED → 执行动作：
   - `AUTO_ASSIGN_TASK` → `TaskService.assign`（任务日志记 ASSIGN）
   - `OPS_*`（A5 审批动作注册表）→ `ApprovalActionRegistry.execute`：动作一致性校验（toolName 还原编码必须与登记一致，防伪造）→ 委托人复核（有效+权限，H2 语义）→ precheck 复核（目标存在性）→ OpsTool executor 以委托人身份执行 → 结果回写 evidence_json（executedAt/executedAs/resultPreview）
4. 无动作的纯建议：仅状态流转

**A5 审批动作注册表（白名单 deny by default）**：11 个 Ops 写工具动作化——
`OPS_TASK_CREATE` / `OPS_TASK_CHANGESTATUS` / `OPS_TASK_ADDWORKHOUR` / `OPS_PROJECT_CREATE` /
`OPS_CONTRACT_BINDPROJECT` / `OPS_TENDER_UPDATESTATUS` / `OPS_COST_SETTLE` /
`OPS_AFTERMARKET_REPAIRCREATE` / `OPS_ARCHIVE_BORROW` / `OPS_ARCHIVE_RETURN` / `OPS_EVENT_HANDLE`。
明确排除：`ecn.approve`（审批本身，Agent 不可代批）、`tender.collect`（同步外呼，走 AGT-27 队列版）。
审批参数结构：`{"actingUserId":<委托人>,"toolName":"<OpsTool名>","params":{<工具参数>}}`（HMAC 锁定）。
生成入口：`DecisionAdviceService.requestToolApproval(toolName, params, actingUserId, reason)`
（B4 MCP 写工具 / B5 Hermes auth-required 回调映射调用；scene=TOOL_APPROVAL，riskLevel=MEDIUM，SLA 24h）。

### 1.3 驳回建议

```
POST /api/v1/agent-advices/{id}/reject
Authorization: Bearer <JWT>（仅 ROLE_DEPT_LEADER）
Body: {"comment": "应指派给李工"}
```

**错误码**：404 建议不存在；409 已处理/完整性校验失败；400 动作参数缺失；500 参数解析失败。

## 2. MCP Server 接口（Dify / Hermes 接入点）

### 2.1 端点与鉴权

```
POST http://localhost:8081/api/mcp
Content-Type: application/json
X-API-Key: <app.mcp.api-key>        # 或 Authorization: Bearer <key>
X-Acting-User-Id: <委托发起人用户ID>  # A4 身份透传（可选）
```

- 传输：MCP Streamable HTTP（单请求-单响应 application/json；无 SSE 流，GET/DELETE → 405）
- 协议：JSON-RPC 2.0；协议版本支持 2024-11-05 / 2025-03-26 / 2025-06-18 / 2026-07-28（回显客户端请求版本，未知回退 2025-06-18）
- 鉴权失败：HTTP 401（BusinessException 语义）

**身份透传（A4）**：`X-Acting-User-Id` 为工具执行身份（委托发起人）——
①有效用户（存在且未禁用）→ 以该身份执行，并逐调用做权限校验（复用 SystemOpsService.checkPerm：
部门领导兜底 + minRole/permCode 双重声明；拒绝时 isError=true + 业务可读文案）；
②无效/禁用用户 → 工具执行拒绝（isError=true，「X-Acting-User-Id 对应用户无效或已禁用」）；
③未携带/非法值 → 回落系统委托身份 `app.mcp.acting-user-id`（默认 1）。
Hermes 侧在 mcp_servers.dept-mgmt.headers 配置 `X-Acting-User-Id: "1"`（**必须加引号**——
YAML 裸数字被解析为 int，httpx 拒绝并致连接超时失败）；B 阶段由 HermesService 动态携带。

## 3. 网关 OpenAI 兼容门面（Hermes / Dify 统一模型入口）

```
POST http://localhost:8090/v1/chat/completions
Authorization: Bearer <网关密钥>    # 或 X-API-Key 头
Content-Type: application/json

{"model":"gateway-auto","messages":[{"role":"user","content":"..."}],"max_tokens":512,"stream":false}
```

**行为**：
- messages 合并为单 prompt 走网关治理流水线（OPENAI_COMPAT 能力点校验 → 35 次/分限流 → 日配额 → 脱敏 → Provider 降级链 → 审计）
- 响应为标准 OpenAI 形状（id/object/choices/usage）；全链失败时返回降级文案并附 `gateway_degraded: true`
- `stream:true` → SSE 单分片仿真流（内容一次性下发 + `data: [DONE]`；真流式为阶段二）
- `model` 参数仅透传记录，实际通道由网关按启用链优先级选择（LM→NVIDIA→MOCK）
- 鉴权失败：HTTP 401（JSON-RPC/JSON 错误体）
- 能力点种子：`database/10_gateway_facade.sql`（OPENAI_COMPAT，幂等）

## 4. Hermes Agent 配置（实测格式，v0.22.5，2026-11-17 A1/A2 定稿）

**配置文件真实路径：`C:\Users\<user>\AppData\Local\hermes\config.yaml`**（`hermes config path` 输出为准；
`~\.hermes\config.yaml` 不被读取——此前 429 根因即写错了位置）。环境变量文件：`...\Local\hermes\.env`。

### 4.1 模型绑定（providers 条目 + model 块）

```yaml
providers:
  dept-gateway:               # 运行时 id：custom:dept-gateway
    name: dept-gateway
    base_url: http://localhost:8090/v1
    api_key: <网关密钥>
    default_model: gateway-auto
    context_length: 64000
    models:
      gateway-auto:
        context_length: 64000

model:
  default: gateway-auto
  provider: custom:dept-gateway
  context_length: 64000
```

要点：provider 条目键为 `name/base_url/api_key/default_model`（不是 `provider/model/base_url` 嵌套 dict）；
默认 api_mode 即 OpenAI chat_completions（anthropic 需显式 `api_mode: anthropic`）。

### 4.2 MCP Server（顶层 `mcp_servers`）

```yaml
mcp_servers:
  dept-mgmt:
    url: http://localhost:8081/api/mcp
    headers:
      X-API-Key: <app.mcp.api-key>
    connect_timeout: 15
    enabled: true
```

**硬依赖**：Hermes venv 必须安装 MCP SDK（缺包时 MCP 工具静默跳过）：
`& "$env:LOCALAPPDATA\hermes\hermes-agent\venv\Scripts\python.exe" -m pip install mcp`

### 4.3 MCP 工具命名（Hermes 侧注册名）

`mcp__<server 下划线化>__<tool 点号下划线化>`，如：
`mcp__dept_mgmt__task_my_todo` / `mcp__dept_mgmt__project_query`（backend 侧原名 `task.my_todo`）。

### 4.4 API Server（A1 服务化常驻）

- 环境变量（写入 `...\Local\hermes\.env`）：`API_SERVER_ENABLED=true`、`API_SERVER_HOST=127.0.0.1`、
  `API_SERVER_PORT=8642`、`API_SERVER_KEY=<Bearer 密钥>`

- 端点：`/v1/chat/completions`、`/v1/runs`、`/v1/runs/{id}`、`/v1/runs/{id}/approval`、`/v1/models`、`/health`

验证：`hermes -z "..."` one-shot 调用后查 `sys_ai_call_log WHERE caller_id='openai-compat'` 确认经门面审计。

### 4.5 对话第四级路由——Hermes 委托协议（B2，2026-11-17 定稿）

**路由链**（`AiChatService.routeAndReply`，自上而下首个命中即返回）：

| 级 | 判定 | 实现 | 响应形态 |
| --- | --- | --- | --- |
| 1 | 流程创建意图（正则） | AiChatService | workflow 卡片 |
| 2 | 系统操作意图（LLM 判定 tool/ask） | SystemOpsService.tryOps | text/追问卡片 |
| 3 | Agent 能力点（关键词规则置信度 ≥0.5） | MasterAgentService.submitAs | task 卡片 |
| 4 | 复杂多步/跨模块委托（启发式 + Hermes 可用） | HermesDelegateService.tryDelegate | **hermes 卡片** |
| 5 | 兜底 | generalChat（网关通用对话） | text |

**第四级委托判定（`shouldDelegate`，不耗 LLM 配额）**：长度 ≥8；排除纯查询短指令（<30 字）；命中触发词
（委托/交给/帮我处理|办理|跟进|协调|排查|整理/跨模块|跨部门/生成报告周报日报月报总结/汇总/对比分析）
或（长度 ≥25 且多步串联词 然后|之后|同时|再|并且）。

**委托执行**：`submitRun(任务书)` → 立即回复 hermes 卡片（`msg_type=hermes`，
content 头部内嵌 `<!-- hermes-run:<runId> -->` 标记供前端/B3 过程关联）→
后台单线程 daemon（`hermes-delegate-poll`）`awaitRun` 轮询（2s 间隔，超时 600s）：

- 成功（completed）：回写 `**AI Agent 员工执行完成**` + output；
- 失败：回写失败说明 + error；超时：回写超时提示并 `stopRun`；
- 全程不阻塞 chat HTTP 线程；Hermes 不可用/提交失败 → 返回 null 降级第五级通用对话。

**任务书**：系统约束（AI Agent 员工身份 + 27 个 MCP 工具 + 不越权 + 审批中断说明）
+ 委托人 userId/username（MCP 工具以该身份执行，走 A4 透传链）+ 用户原话。

**降级开关**：`app.hermes.enabled=false` 或 `/health` 探测失败（30s 缓存）→ 委托层自动跳过。

**已知问题**（记录于 C4 前跟进）：LM gemma-4-e2b 流式响应无 finish_reason（Clean EOF）
导致部分 run 判 failed（output 有值）——客户端终态语义正确处理；小模型可能不自发调用 MCP
工具（文本索要工具名），换稳定模型为候选优化；委托判定为启发式，阶段二演进 LLM 意图判别。

### 4.6 执行过程回写——run 事件时间线（B3，2026-11-17 定稿）

**事件源**：Hermes 原生 `GET /v1/runs/{id}/events`（SSE，Bearer 认证）——连接即重放 backlog
（`seq` 序号 + Last-Event-ID 语义），随 run 生命周期推送结构化事件；终态后服务端发 close 哨兵。

**消费链路**：委托提交后，后台线程（hermes-delegate-poll）先 `consumeEvents`（HttpURLConnection
逐行解析 `data:` 帧）再 `awaitRun` 终态轮询——事件流失败/读超时（30s）静默降级，不影响终态回写。

**入库白名单**（表 `hermes_run_event`，DDL `database/11_hermes_run_event.sql`，(run_id, seq) 唯一幂等）：

| 事件 | 字段映射 |
| --- | --- |
| tool.started | tool / preview（参数预览） |
| tool.completed | tool / duration（秒→毫秒）/ error→is_error / preview（结果预览，Hermes 侧已脱敏截断 500 字符） |
| approval.request | preview（审批请求摘要，B5 双向闭环数据源） |
| message.interim / subagent.start / subagent.complete | text/preview |
| run.completed / run.failed / run.cancelled / run.interrupted / run.steered | error→preview |

丢弃：`message.delta`（逐 token 噪声）、`reasoning.available`、`replay.truncated`、`approval.responded`。

**查询接口**：`GET /api/v1/ai/ws/hermes/runs/{runId}/events`（登录态）——经 ai_message 内嵌标记
`<!-- hermes-run:{runId} -->` 反查会话并校验归属（非本人/未知 run 返回 code=404「委托任务不存在」），
返回按 seq 升序事件列表（≤200 条），前端据此绘制执行时间线。

**写工具清单**（与 A5 ApprovalActionRegistry 白名单一致）：task.create / task.changeStatus /
task.addWorkHour / project.create / contract.bindProject / tender.updateStatus / cost.settle /
aftermarket.repairCreate / archive.borrow / archive.return / event.handle。
白名单外写工具（ecn.approve / tender.collect）不暴露（deny-by-default）。

**tools/list 写声明**：`requiresApproval: true` + `annotations.readOnlyHint: false`；
写工具 description 尾部追加「写操作·requiresApproval=true：调用即生成待确认审批建议…本工具不直接写入」。

**写工具调用语义**（tools/call）：X-Acting-User-Id 身份校验（A4 链）→ checkPermission（403 即拒）
→ requestToolApproval 生成 TOOL_APPROVAL 场景 PENDING 建议（HMAC 锁定参数，委托人 24h 有效）→
返回 `{approvalRequired:true, adviceId, toolName, title, message}`。

### 4.8 审批回调双向闭环——B5（2026-11-17 定稿）

**中断检测**：委托后台轮询（`pollDetectingApproval`，2s 间隔 / 600s 上限）检测 run
`status=waiting_for_approval`——从 `status.approval.request_id` + description/command（Hermes 侧已脱敏）
提取审批请求 → `createHermesApproval` 生成建议（幂等：同 requestId 仅一条 PENDING）。
事件流消费（B3 SSE）与轮询分线程执行——审批等待期 SSE 流保持打开不阻塞轮询。

**建议形态**（场景 `HERMES_APPROVAL`，动作 `HERMES_RESOLVE`）：
approval_params_json={runId, requestId, actingUserId}（HMAC-SHA256 锁定，密钥 app.advice.hmac-secret）；
委托人为站内信接收人（targetUserId），24h SLA。

**双向回调**（POST /api/v1/agent-advices/{id}/approve | /reject，仅 ROLE_DEPT_LEADER）：

| 操作 | 语义 | Hermes 回调 |
| --- | --- | --- |
| 采纳 | HMAC 校验 → 状态 APPROVED → resolveApproval(runId, requestId, **once**) 恢复执行 | `POST /v1/runs/{id}/approval {"choice":"once","request_id":...}` |
| 驳回 | 状态 REJECTED → resolveApproval(runId, requestId, **deny**) 终止执行 | 同上 choice=deny |

回调失败（Hermes 不可达/审批不活跃）→ resolveApproval 返回 false → 503 异常**回滚审批状态流转**
（建议保持 PENDING 可重试）；resolveApproval 已由 void 改返回 boolean。

**已知限制**：waiting_for_approval 端到端真实验证依赖模型实际触发敏感操作——gemma-4-e2b
不执行工具（B2 已知问题），建议生成与回调成功路径由单测覆盖 + 回调失败路径真实链路实测；
C3 换稳定模型后补端到端验证。
