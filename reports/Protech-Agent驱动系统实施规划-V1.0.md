## 〇、关键前置决策（必须在 Phase 0 结束前拍板）

| 编号 | 决策项 | 影响 | 建议结论 |
|---|---|---|---|

| D-06 | **数据准备责任人**（Q-10/11/12/13） | 主数据与知识库进度 | 物料先导 1200 码；8 工作流 SOP + 12 部门 SOP 作为知识库首批语料 |

## 一、阶段划分与交付物

```
Phase 0 准备与加固(1.5周) → Phase 1 Agent地基+主链路上半程(7周)
→ Phase 2 业务主干+看板(8周) → Phase 3 扩展深化(8周) → Phase 4 移动端与开放(3周)
里程碑：M1 第1月末地基就绪 / M2 第3月末合同→设计跑通 / M3 第5月末一期上线
       / M4 第9月末二期上线 / M5 第12月三期完成
```

### Phase 0：准备与加固（第 1–1.5 周，约 12 PD）

**核心目标**：决策确认、开发环境就绪、复用代码安全整改完成、数据准备启动。

| 交付物 | 说明 |
|---|---|
| 决策确认清单 | D-01~D-06 全部书面确认（老板/决策层） |
| 开发环境 | Git 仓库与分支策略、Docker Compose（MySQL/Redis/RabbitMQ/Ollama/MinIO）、CI 脚本 |
| 安全加固基线 | 修复审计报告 H1/H2/H4/H5（接口级权限控制、重置密码越权、凭据环境变量化、JWT 密钥治理、登录防爆破）——Agent 以用户身份执行会放大越权漏洞，此项为**不可跳过的红线** |
| 代码库复用清单 | 见 3.1 节复用映射表 |
| 数据准备任务书 | 物料归一清单、合同存量清洗、SOP 语料收集的责任人与时间表 |

## 三、技术实现要点与规范标准

### 3.1 复用映射表（当前代码库 → 新系统）

| 现有模块 | 处置 | 说明 |
|---|---|---|
| 用户/角色/部门（sys_user 等） | **复用扩展** | 增加 12 部门角色与三身份模型 |
| JWT 认证链（JwtUtils/SecurityConfig） | **复用+整改** | 必须先完成 T-002 安全整改 |
| R/PageResult/GlobalExceptionHandler/OperLog 审计 | **直接复用** | 全局规范沿用 |
| 文件上传链路（FileInfo/FileVersion/审核/归档） | **复用改造** | 上传根路径改 MinIO，增加水印；修复文件名穿越问题（FileService.java:102-108） |
| 消息中心/公告 | **复用** | 作为 Agent 通知通道之一 |
| 前端 Vue3+ElementPlus 骨架/路由守卫 | **复用扩展** | 增加 Agent 工作台组件层 |
| uni-app 小程序壳与 request 封装 | **复用** | 修复 BASE='/api' 真机问题（改环境变量注入完整域名） |
| AiService（Ollama 对接） | **改造为网关下游** | Provider 抽象替代单点 RestTemplate |
| KPI/精益/任务池等旧业务模块 | **保留但冻结迭代** | 新系统按 8 工作流重建，旧模块数据迁出后归档 |

### 3.2 架构要点

1. **模块化单体**：4 进程（app/ai-gateway/file-service/job-worker），模块间只经事件总线（RabbitMQ + 本地事件表兜底）通信，禁止跨模块直读表；事件消费必须幂等（事件 ID 去重）。
2. **AI 网关唯一出口**：任何业务代码不得直连模型 SDK/URL（静态扫描 0 命中）；网关承担能力注册、配额、脱敏、审计、降级链、双通道路由；输出强制 JSON 契约校验，失败重生成一次后转人工。
3. **三身份权限引擎**：有效权限 = min(身份基线, 被代理人权限, 能力白名单)；审批/资金/主数据建档/删除四类操作永久 Never。
4. **渐进自主引擎**：四级状态机由定时任务按采纳率数据自动升降级（升级门槛见 V2 §3.4），任何一周错误率>10% 自动降级并通知管理员。
5. **业务规则配置化**：BR-01~BR-09、收款比例区间、验收节点阈值全部存库可配，不硬编码（应对规则变更风险）。
6. **降级链**：模型不可用→人工模式；钉钉不可用→站内通知；T+ API 不可用→文件适配器。Agent 是增强不是依赖，任何 Agent 故障不得阻塞业务主流程。

### 3.3 数据与编码规范

- **能选不填**：主数据字段一律下拉+搜索，服务端拒绝自由文本；模糊匹配走 AGT-12。
- **一次录入多处引用**：所有联动走事件总线，禁止人工跨模块补录。
- 数据库规范：金额 DECIMAL(18,2) 禁用 float；全部表带 created_by/updated_by（含 Agent 标识 `agent:{userId}:{能力编号}`）、软删除标志、utf8mb4；审计日志保留 1 年、AI 调用日志 2 年。
- 后端：接口级权限注解强制（@PreAuthorize）；统一异常处理不外泄堆栈；日志脱敏（手机号/金额）。
- 前端：组件按“业务域/Agent 组件/公共”三层组织；建议卡片、操作日志做成全局公共组件。
- Git：main 保护 + feature 分支 + 每切片一个 release 分支；commit 格式 `[{切片}] {模块} {描述}`。

### 3.4 AI 工程规范

- 提示词版本管理入库（可回滚、可 A/B）；每个能力点登记：输入契约、输出 JSON Schema、置信度阈值、质量标准、自主级别。
- 数值计算一律代码算、模型只组织表述（禁止模型算钱）；知识类输出强制溯源引用，置信不足明示“不确定”。
- 敏感场景（合同金额/客户信息）强制本地模型；出网 API 必经脱敏（人名→角色、金额→脱敏码）。
