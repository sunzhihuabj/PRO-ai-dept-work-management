1. 背景与目标

1.1 现状证据

系统已建成完整的部门工作管理业务闭环：项目管理（项目/阶段/阶段门/交付物清单）、任务管理（任务/子任务/工时/任务池）、文件链路（上传→版本→审核→归档台账）、绩效考核（指标/权重/评分计算/发布）、精益改进（A3 报告/浪费记录/价值流/根因分析）、奖金管理、审核事件、公告与消息，并具备初步 AI 能力：

现有 AI 能力实现方式局限
日报/周报/会议纪要摘要（/v1/ai/summary）用户粘贴文本 → Ollama（qwen2.5:7b）单轮生成需人工整理素材、复制粘贴；不感知系统数据；结果无人审核闭环
文件版本差异分析（/v1/files/{id}/diff）读取两个版本文本文件拼接 prompt 分析仅限 ≤1MB 文本文件；结果一次性展示，不沉淀、不触发后续动作

核心问题：AI 仅作为"单点问答工具"存在，未与业务流程、数据、权限打通。大量高频、规则明确、重复性强的工作仍完全依赖人工：员工每日整理素材写日报、档案员逐个判断文件分类与版本说明、审核员逐条阅读事件描述做分流、项目负责人逐项核对阶段交付物是否齐套、部门领导汇总各项目进展做周会材料。这些工作的共同特征是：输入结构化程度高、判断规则可枚举、输出格式标准化、执行结果可校验——恰好是 AI Agent 自动化的理想区间。

1.2 产品响应与目标

证据/问题受影响用户与时刻产品决策预期可观测结果
员工手动整理素材写日报/周报，耗时且格式不一全体成员，每日下班前/周五Agent 自动汇聚本人当日任务进展、工时、文件、消息，生成草稿供一键提交日报草稿在待办中就绪，用户确认即完成
档案员人工判断文件分类、命名、版本说明，易漏归档档案员，每次上传后Agent 读取文件元数据与内容摘要，自动生成分类/命名/说明建议，低风险场景直接归档新上传文件秒级获得归档建议，齐套缺口自动预警
审核事件靠人工阅读分流，响应慢审核员/部门领导，事件产生时Agent 自动解析事件类型、风险等级、建议处理人与处理路径事件产生后自动带分流建议进入处理队列
阶段门齐套性人工逐项核对项目负责人，阶段评审前Agent 定期自动比对交付物清单与已上传文件评审前自动生成齐套性报告与缺口清单
管理层数据汇总靠人工导出拼表部门领导，周例会/月度考核Agent 定时生成经营摘要与 KPI 异常预警周报/月报自动生成并推送待办

总目标：将 AI 从"问答工具"升级为"可调度、可审计、可回滚的数字员工"，凡是 Agent 能稳定、安全、高效完成的工作全部交由 Agent 执行，人只负责确认关键决策与处理例外。

2. 产品契约与术语

要素定义
主要用户① 全体员工（Agent 服务的受益人，也是人机协作的确认者）；② 部门领导（自动化策略的审批人、效果监督人）；③ 系统管理员（Agent 工具、权限、自动化策略的配置人）
触发条件四类触发：定时触发（如每日 17:30 生成日报草稿）、事件触发（如文件上传完成、任务状态变更、事件创建）、用户指令触发（在 Agent 助手对话中下达）、流程节点触发（如阶段门评审申请提交时自动预检）
核心任务把系统内已有的结构化数据转化为可直接执行的产出物（报告、建议、分类结果、预警），并在授权范围内代替人执行可逆操作
完成条件Agent 任务以四种终态之一结束：已完成（产出物送达并被人确认 / 可逆操作已执行并写入台账）、已转人工（失败或低置信度后进入人工待办）、已取消、已回滚
共享业务对象Agent 任务单（AgentTask）：一次自动化执行的唯一载体，承载触发来源、目标场景、执行轨迹、产出物、人工确认记录与审计信息（见 4.2）
信任机制Agent 继承发起人/配置人的数据权限与角色边界；所有动作留痕于任务台账与操作日志；高风险操作强制人工确认；任何自动化结果可追溯、可撤销

术语表：Agent=具备感知（读取系统数据）→ 规划（拆解步骤）→ 行动（调用系统工具）→ 复核（校验结果）能力的自动化执行体；工具（Tool）=Agent 可调用的一个系统能力单元（如"创建公告""归档文件"）；编排=按场景脚本或模型规划组合多个工具调用的过程；自动化等级 L0–L3 见第 6 章。

3. 建设范围

3.1 P0 最小完整旅程

旅程定义：员工 A 在某工作日产生任务进展与文件产出 → 系统定时触发日报 Agent → Agent 汇聚数据生成日报草稿 → 进入 A 的待办 → A 审阅并一键确认提交 → 产出物归档并可追溯。该旅程覆盖：触发机制、数据汇聚、生成、人工确认、留痕回收的完整闭环，是全部后续场景复用的骨架。

P0 必备能力：Agent 任务调度引擎（定时+事件触发）、Agent 助手对话入口、日报/周报生成场景、任务台账与审计、人工确认与转人工机制、Agent 失败降级。

3.2 P1 支持能力

文件智能归档（建议+自动执行）、审核事件智能分流、阶段门齐套性预检、KPI 异常预警、任务拆解与分派建议、消息摘要推送、操作日志异常检测、奖金计算复核、多 Agent 协作、知识库检索增强。

3.3 明确排除项

  • L3 自动执行不可逆动作（物理删除数据、资金发放、账号删除/权限变更、对外发布）——本期一律不开放，仅保留架构位；
  • AI 替代制度性审批决定（文件审核通过/驳回、阶段门评审结论、KPI 最终评分、奖金审批）——AI 只做预检与建议，结论必须由人签发；
  • 跨部门/外部系统（微信生态深度对接、OA 对接）的自动化——不在本期范围。

4. 角色与对象模型

4.1 角色

沿用系统现有 7 角色体系（部门领导/项目负责人/技改负责人/技术员/研发人员/档案管理员/审核员），不新增人工角色。新增一个系统执行主体：

主体性质权限边界
AI Agent系统执行主体（非登录用户），以发起人身份+Agent 标识执行仅能调用工具白名单内的能力；数据可见范围 ≤ 发起人的数据权限；写操作受自动化等级约束；全部动作留痕

4.2 Agent 任务单（AgentTask）状态机

状态含义允许的后续状态
已排队 created/queued触发成功，等待执行资源执行中、已取消
执行中 runningAgent 正在规划/调用工具待人工确认、已完成、已失败→转人工
待人工确认 pending_confirmL1 级产出物就绪，等待确认（默认 72 小时 TTL，超时转人工待办）已完成、已驳回→转人工、已取消
已完成 done产出物送达/操作已执行并登记已回滚（仅 L2 可逆操作）
已转人工 escalated失败重试耗尽/低置信度/确认超时，生成人工待办终态（人工完成后由人工任务独立流转）
已失败 failed执行异常，进入重试计数已排队（重试，指数退避，最多 3 次）、已转人工
已取消 cancelled / 已回滚 rolled_back人工取消 / L2 操作撤销并恢复原状终态

6. Agent 能力边界与人机协作原则

6.1 落地总原则

凡是 Agent 可稳定、安全、高效完成的工作全部交由 Agent 执行，落地为三条判定规则（同时满足方可自动化）：

  • 稳定性：任务的输入可枚举、判断规则可表达、历史人工正确率可被 Agent 达到（以试点期准确率 ≥90% 且连续 2 周无重大错判为准入门槛 [Assumption, TBD]）；
  • 安全性：操作要么只读、要么可逆可回滚；涉及金钱、权限、审批结论、对外发布的动作一律不自动执行；
  • 高效性：自动化端到端耗时 ≤ 人工路径的 1/2，否则保留人工。

6.2 自动化等级与权责划分

等级定义典型场景Agent 权责人的权责
L0 信息呈现AI 只读数据生成报告/预警，直接推送，不写业务数据S3 晨报、S7 齐套报告、S10 预检、S12 风险清单保证数据准确、按时送达；对报告数据完整性负责阅读并自行决策；可反馈误报
L1 草稿待确认AI 生成草稿/建议，人一键确认后生效S1 日报、S5 归档建议、S9 事件分流、S11 任务拆解、S13 KPI 复核清单草稿质量、依据可解释（列出数据来源）；超时自动转人工最终决定权：确认/编辑/驳回；驳回理由反哺优化
L2 可逆自动AI 直接执行可逆操作（自动撤销窗口内可一键回滚），事后审计S6 自动归档（可取消归档恢复）执行前自检规则命中；执行后登记台账；错误操作负责发现并提示回滚事后抽检；发现错误发起回滚
L3 受控高危不可逆/高后果动作，本期禁止自动执行删除数据、奖金发放、审批结论、权限变更仅可产出执行草案必须由人操作；架构预留双确认位

6.3 触发机制与确认机制

触发源：定时 / 事件 / 指令 / 流程节点→ 调度引擎：生成 AgentTask（排队）→ Agent 执行：读数据 → 规划 → 调工具 → 自检→ 等级路由：L0 直达送达 ｜ L1 进入待人工确认 ｜ L2 执行+登记回滚点→ 终态登记：台账 + 操作日志 + 通知发起人
  • 确认入口统一：所有待确认项集中在「Agent 待办」卡片（工作台 + 消息中心 + 小程序消息页三端可见），展示产出物预览、数据依据、来源任务单号；
  • 确认超时：L1 待确认默认 72 小时 TTL，超时自动转人工待办并通知发起人 [Assumption, TTL 可配置]；
  • 回滚窗口：L2 操作默认保留 24 小时一键回滚窗口 [Assumption, 可配置]，回滚同样留痕。

7. Agent 能力架构方案

架构按产品能力模块描述（实现选型不做约束），与现有系统关系：Agent 不绕过现有接口与权限体系，而是作为新的执行主体接入既有业务层。

能力模块职责（产品视角）与现有系统的集成方式
① Agent 网关与对话入口统一受理指令触发与会话；PC 端「AI 助手」升级为可执行指令的助手，小程序提供轻量对话与待办确认前端复用现有登录与路由体系；PC 在 AiAssistant 页面升级，小程序新增消息确认入口；复用现有 JWT 认证链
② 任务调度引擎四类触发的统一受理、排队、并发控制、重试退避、TTL 超时、优先级（人工指令 > 事件 > 定时）；AgentTask 生命周期管理后端新增调度与执行模块，独立于现有同步接口；复用现有异步线程池配置，扩容独立执行队列
③ 工具集（Tool 注册中心）把系统能力封装为带权限标注、参数契约、风险等级的标准工具：任务读写、文件归档、公告发送、消息推送、数据统计查询等；新增场景=注册新工具，不改核心引擎工具直接映射现有 service 层能力；禁止工具越权访问发起人权限外的数据
④ 编排与多 Agent 协作单场景内按脚本编排多工具；跨场景时由调度 Agent 分派给专项 Agent（日报 Agent、归档 Agent、预警 Agent、质检 Agent），互相通过任务单交接，不直接互调协作上下文通过 AgentTask 关联（父子任务单），全程留痕
⑤ 知识库与记忆短期记忆=单任务上下文；长期记忆=场景模板、历史产出物、人工修正记录（用于提升草稿质量与个性化）；检索增强=项目制度/模板文档沉淀为系统内数据资产（模板表、修正记录），供生成时引用
⑥ 模型服务适配层统一对接大模型（当前 Ollama qwen2.5:7b），屏蔽模型差异；输出结构化校验（JSON 契约），校验失败自动重生成或降级复用现有 AiService 配置位（base-url/model/timeout），模型可替换
⑦ 安全管控体系身份与权限继承、工具白名单、敏感词与提示注入防护、产出物内容审核（低置信度拦截）、全量审计、限流熔断、人工紧急停机开关（一键暂停全部 Agent）依赖并前置修复现有鉴权短板（见 7.1 风险提示）
7.1 前置依赖（安全红线）：代码安全审计已确认当前系统存在接口级权限控制缺失等高危问题（详见《代码库架构梳理与安全审计报告》H1–H5）。Agent 以用户身份批量调用系统能力，会放大任何既有越权漏洞的后果。因此「接口级权限控制落地」是 Agent 体系建设的前置必须项，列入阶段一第 0 步；JWT 凭据环境变量化、登录防爆破同步完成。

7.2 多 Agent 协作机制（产品规则）

  • 分派规则：调度 Agent 按"场景编号"路由到唯一专项 Agent；一个用户指令若涉及多场景（如"帮我整理本周进展并检查交付物缺口"），拆为多个子任务单，串行/并行执行后聚合回复；
  • 冲突规则：两个 Agent 对同一业务对象产生写冲突时（如同时操作同一文件归档），按任务单优先级与创建时间串行化，后到者等待；
  • 升级规则：专项 Agent 连续 2 次执行失败或置信度低于阈值 → 任务转人工，并在 Agent 待办中说明失败原因与已尝试步骤。

9. 共享规则

规则内容
R1 身份与权限继承Agent 永远以"发起人身份 + Agent 标识"执行：数据可见范围、可操作对象均 ≤ 发起人权限；定时/事件触发的系统任务以场景配置人身份执行。所有 Agent 产出的业务记录在创建人字段带 Agent 标识，台账可区分人机操作。
R2 确认与回滚L1 待确认 TTL 默认 72h，超时转人工；L2 回滚窗口默认 24h。确认/驳回/回滚均登记操作人与时间；驳回必填原因并写入记忆（FR-08）。
R3 失败降级与重试模型或工具失败：按指数退避重试最多 3 次（1min/5min/30min）[Assumption]，仍失败→任务转人工待办并通知发起人；模型服务连续不可用超 15 分钟，所有定时场景自动挂起，恢复后自动补跑当期 [Assumption]。
R4 内容安全外部内容（文件内容、事件描述）进入模型前做注入标记隔离；模型输出必须通过结构化契约校验，校验失败自动重生成一次，再失败转人工；输出含敏感操作指令（删除/改权限/转账等语义）一律拦截不执行。
R5 审计与限流每任务全轨迹留痕；单用户指令触发限流（每分钟 ≤5 次任务 [Assumption]）；系统级并发上限可配置，超出排队。
R6 通知时机与接收人产出送达、待确认、转人工、回滚完成四类事件通知发起人/相关人；通知渠道复用现有消息中心（站内+小程序），不新增渠道。
R7 计算与置信度涉及数值的产出（工时估算、齐套统计）一律来自系统数据直取，不由模型计算数值；模型仅负责组织表述。所有建议类输出附带置信度标注，低于阈值不预填。
