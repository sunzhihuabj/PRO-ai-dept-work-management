# 精细化权限配置接口说明 V1.0（T-404）

> 基础路径：`/api/v1/fine-perms` ｜ 认证：Bearer JWT（Authorization 头）
> 通用响应结构：`{ code, msg, data, success }`；分页结构：`{ records, total, size, current, pages }`
> 标注 ⓐ 的接口需 `api:system/perm-config:*` 权限点（ROLE_DEPT_LEADER 兜底放行，灰度用户未启用精细控制时放行）

---

## 一、权限点与分配

### 1.1 权限点树
```
GET /v1/fine-perms/points
```
- 响应 data：`PermPointNode[]`——`{ permCode, permName, permType(MENU/BUTTON/API), children[] }`
- MENU 为根节点，BUTTON/API 挂于对应 MENU 的 children。

### 1.2 查询主体分配
```
GET /v1/fine-perms/assignments?subjectType=DEPT|POSITION&subjectId={id}
```
- 响应 data：`SysPermAssignment[]`——`{ id, subjectType, subjectId, permCode, permType, effect(GRANT/DENY) }`

### 1.3 批量分配 ⓐ
```
POST /v1/fine-perms/assignments
{ "subjectType": "POSITION", "subjectId": 5,
  "permCodes": ["btn:system/user:list", "api:system/user:list"],
  "effect": "GRANT", "remark": "开通用户管理" }
```
- 逐条 upsert（同主体同权限点唯一）；effect=GRANT 授予 / DENY 拒绝。
- 校验：主体存在、效果合法、权限点必须已登记。
- 副作用：写变更日志（before/after 快照）+ 全局版本号递增（实时生效）。
- 响应 data：本次分配条数。

### 1.4 批量移除 ⓐ
```
PUT /v1/fine-perms/assignments/remove
{ "subjectType": "DEPT", "subjectId": 1, "permCodes": ["btn:system/user:create"], "effect": "GRANT" }
```
- effect 字段忽略（结构复用）；响应 data：移除条数。

### 1.5 清空主体 ⓐ
```
POST /v1/fine-perms/assignments/clear
{ "subjectType": "POSITION", "subjectId": 5, "remark": "岗位调整" }
```
- 响应 data：清除条数。

## 二、权限预览与实时生效

### 2.1 预览指定用户 ⓐ
```
GET /v1/fine-perms/preview?userId={id}
```
- 响应 data：`FinePermPreview`
```json
{
  "userId": 4, "username": "yangshuang", "realName": "杨双", "deptName": "技改组",
  "finePermEnabled": true,
  "version": 9,
  "dimensions": [
    { "dimension": "TEMP", "sourceName": "临时评审专家（2026-11-01 ~ 2026-11-30）",
      "sourceId": 3, "perms": ["btn:system/user:list:GRANT"] }
  ],
  "conflicts": [
    { "permCode": "api:system/user:list",
      "detail": "TEMP=GRANT DEPT=DENY → 按优先级(临时>固定>部门)裁决为 GRANT",
      "finalEffect": "GRANT" }
  ],
  "grantedPerms": ["/system/user", "api:system/user:list"],
  "grantedMenus": ["/system/user"],
  "roles": ["ROLE_TECHNICIAN"]
}
```
- `finePermEnabled=false` 表示三维度均未配置（灰度：不启用精细控制）。

### 2.2 自助预览（登录即可）
```
GET /v1/fine-perms/preview/me
```

### 2.3 全局权限版本号（前端轮询）
```
GET /v1/fine-perms/version
```
- 响应 data：long。任何权限配置变更递增；前端路由切换时比对（30s 节流），变化即重新拉取 /v1/auth/me。

## 三、职位管理

### 3.1 职位列表
```
GET /v1/fine-perms/positions
```
- data：`[{ id, positionCode, positionName, description, status, holderCount }]`

### 3.2 创建 / 更新 / 删除职位 ⓐ
```
POST /v1/fine-perms/positions          { "positionCode": "PRJ_SPECIALIST", "positionName": "项目专员", "description": "..." }
PUT  /v1/fine-perms/positions/{id}     { "positionName": "...", "status": 0, "description": "..." }
DELETE /v1/fine-perms/positions/{id}   （职位被持有时 400 拒绝）
```
- 职位停用（status=0）后其权限立即失效（版本号递增）。

### 3.3 用户职位
```
GET /v1/fine-perms/users/{userId}/positions
→ [{ id, userId, positionId, positionName, positionKind(FIXED/TEMP), startTime, endTime, effective }]

POST /v1/fine-perms/users/{userId}/positions   ⓐ
{ "positionId": 5, "positionKind": "TEMP",
  "startTime": "2026-11-11T00:00:00", "endTime": "2026-12-31T23:59:59", "remark": "阶段评审" }
→ data: 关联ID
校验：TEMP 必须有起止时间且 start < end；同用户同职位去重。

DELETE /v1/fine-perms/user-positions/{id}?remark=xxx   ⓐ
```
- FIXED 无需有效期；TEMP 到期自动失效（合并计算时跳过）。

## 四、权限模板

### 4.1 模板列表 / 创建 / 更新 / 删除 ⓐ（读接口登录即可）
```
GET /v1/fine-perms/templates
→ [{ id, templateCode, templateName, description, items: [{ permCode, permType, effect }] }]

POST /v1/fine-perms/templates
{ "templateCode": "TPL_XXX", "templateName": "模板名", "description": "...",
  "items": [{ "permCode": "btn:system/user:list", "permType": "BUTTON", "effect": "GRANT" }] }

PUT    /v1/fine-perms/templates/{id}   （items 全量替换）
DELETE /v1/fine-perms/templates/{id}
```

### 4.2 应用模板 ⓐ
```
POST /v1/fine-perms/templates/{id}/apply
{ "subjectType": "POSITION", "subjectId": 5, "remark": "新员工入职" }
```
- 模板条目逐条 upsert 到目标主体；响应 data：应用条数。

## 五、变更日志（审计）

```
GET /v1/fine-perms/change-logs ⓐ
    ?subjectType=USER|DEPT|POSITION&subjectId=&operatorName=&dimension=DEPT|FIXED|TEMP|POSITION
    &operation=GRANT|DENY|CLEAR|ASSIGN_POSITION|REMOVE_POSITION|APPLY_TEMPLATE
    &startTime=2026-11-11T00:00:00&endTime=...&pageNo=1&pageSize=20
```
- data：`PageResult<PermChangeLog>`——`{ operatorId, operatorName, subjectType, subjectId, subjectName, dimension, operation, permCodes(JSON数组字符串), beforeJson, afterJson, remark, createTime }`
- beforeJson/afterJson：主体视角快照——分配变更 = `["perm_code:effect", ...]`；职位分配 = `["职位名:FIXED[2026-11-01~2026-11-30]", ...]`。
- 记录失败不阻断业务（日志表写入异常仅告警）。

## 六、安全机制

### 6.1 拦截链路
1. `JwtAuthenticationFilter`：解析 JWT → authorities = 角色（token 内 ROLE_XXX）+ 精细权限点（`FinePermCacheService` 按全局版本缓存，变更即重载）。
2. `FinePermInterceptor`（MVC 拦截器）：方法含 `@RequirePerm` 时校验——
   - 用户未启用精细控制（三维度无任何分配）→ **放行**（灰度原则）；
   - 持有对应 API 权限点 → 放行；
   - 持有 `ROLE_DEPT_LEADER` → **放行**（最高角色兜底防自锁）；
   - 否则 403 `{"code":403,"msg":"无访问权限，缺少接口权限点: api:..."}`。

### 6.2 实时生效实现
- `FinePermCacheService`：`AtomicLong` 全局版本 + `ConcurrentHashMap<userId, CacheEntry(version, enabled, granted)>`。
- 任何配置变更（assign/remove/clear/applyTemplate/职位调整/模板应用）→ `bump()`：版本+1、清缓存 → 下一次请求重载。
- **多实例扩展**：版本号改为 DB 表（如 sys_perm_version）+ 各实例请求时比对 DB 版本（或走 Redis pub/sub 通知），接口与本机制不变。

## 七、错误码约定

| 场景 | 返回 |
|---|---|
| 权限点不存在 | 200/`code=400` "权限点不存在: xxx" |
| 主体（部门/职位）不存在 | 200/`code=404` |
| 临时职位缺有效期 / start≥end | 200/`code=400` |
| 职位被持有删除 | 200/`code=400` "该职位仍被 N 个用户持有" |
| 缺接口权限点 | HTTP 403 |
| 未登录 | HTTP 401 |
