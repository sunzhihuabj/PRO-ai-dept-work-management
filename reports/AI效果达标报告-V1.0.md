## 三、禁止编造体系（V2 Never 红线落地）

V2 明确"Never：编造答案"。落地三道防线（T-307/308 验证）：

1. **指标白名单**：ChatBI 仅回答 sys_metric 注册指标；LLM 意图兜底只做"选指标"（输出 JSON 契约），未命中/越白名单一律 400 拒绝并附白名单清单
2. **数字零 LLM**：全部数字来自 SQL 执行结果（AGT-18/22/25/26 报告类全部模板拼接，口径说明原文引用）
3. **模板与参数安全**：sql_template 执行前二次校验（仅 SELECT/禁危险词/禁注释/禁分号）；参数必须在 params_schema 白名单内（long 严格正整数，杜绝注入通道）

实测反例：注入问题（`逾期采购; DROP TABLE sys_metric;--`）正常命中指标且表未受损；恶意模板（DELETE）入库即拦截；`projectId=1; DROP TABLE project` 类型校验拒绝。

## 四、披露事项

### 4.1 确定性引擎优先原则（自主制定，已披露）
AGT-02/11/12/13/16/17/19/21/22/23/25/26 等 12 个能力点核心逻辑为确定性规则/SQL 引擎，透明可复核。LLM（Mock 通道就绪，商用通道可配置切换）用于 AGT-01/03/06/07/09 等解析/起草类。

### 4.2 Mock 通道说明
当前 AI 通道为 Mock 兜底（开发测试，确定性返回），真实商用通道在界面配置后启用，契约校验器与降级链（网关全链失败→转人工/站内信）不变。涉及 LLM 的验收标准（解析完整率/草稿可用率）以契约结构完整性验证，真实模型效果待商用通道接入后复测。

### 4.3 AGT-10 预留说明
规划文档未明确 AGT-10 语义，注册表标注"预留能力点，编号预留待补"，未实现不影响主链路。如后续明确需求可在现架构上以 Handler 形式补充（约 0.5 人天）。

### 4.4 事件驱动型能力点
AGT-08/15/19/20/24 由领域事件总线触发（非 CapabilityHandler 同步调用），触发口径与幂等已在对应任务冒烟覆盖。
